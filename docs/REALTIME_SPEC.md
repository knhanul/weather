# nuni weather 실시간 기상·예보 통계 확장 개발 요청 (t138u, 2026-10-13 원문)

> 원문 그대로 옮김. 단, 대화 기록에서 5-2 '단기예보와 중기예보를 기간별로 연결한다. 두 예보가 겹치는 날짜는 신뢰할 수 있는 최…' 다음부터
> 8절 '…카드가 반복되지 않도록 한다.' 앞까지 약 2,300자가 잘려서 전달되었다(6·7절과 8절 앞부분). 잘린 부분은 사용자에게 원문을 다시 받아 채울 것.

1. 프로젝트 정보

- GitHub: https://github.com/knhanul/weather.git
- 운영 사이트: https://weather.nuni.co.kr
- 목적: 과거 기상통계 중심의 웹사이트를 실시간 날씨와 향후 예보까지 분석하는 기상정보 서비스로 확장한다.

이 프로젝트의 가장 중요한 목적은 단순한 일기예보 제공이 아니다.

현재와 미래의 날씨가 과거에 비해 얼마나 특별한지 분석하고, 일반 사용자가 흥미를 느낄 수 있는 날씨 이야기를 제공하는 것이다.

예를 들어 다음과 같은 정보를 제공한다.

- "오늘 오후 3시 기온은 1990년 이후 같은 시기 평균보다 4.2℃ 높습니다."
- "최근 5년을 기준으로 하면 평균보다 2.1℃ 높은 수준입니다."
- "이번 주는 최근 10년 같은 시기보다 더울 전망입니다."
- "오늘과 가장 비슷했던 과거의 날은 언제일까요?"
- "내일 최고기온 예보가 과거 같은 날짜의 기록에 근접하고 있습니다."

위 문구의 수치는 가상 예시이며 실제 DB에서 계산한 결과만 표시해야 한다.

2. 기존 시스템 및 데이터 활용 원칙

다음 기상청 데이터를 이미 DB에 적재했다.

1. 기상청 단기예보 조회서비스
   - 초단기실황
   - 초단기예보
   - 단기예보
2. 기상청 중기예보 조회서비스
   - 중기기온
   - 중기육상예보
   - 중기전망
3. 기상청 API허브 ASOS 시간자료
   - 1990년 이후 관측자료
   - 기존 ASOS 일자료도 함께 활용

이미 저장된 데이터를 우선 활용하며 별도의 데이터 수집 시스템을 중복 개발하지 않는다.

개발 전 다음 사항을 확인한다.

- 실제 DB 테이블과 필드 구조
- 데이터 종류별 적재 기간 및 마지막 수집시각
- 관측지점별 자료 보유 현황
- 실황·예보 데이터의 저장 형태
- 기존 통계 엔진과 데이터 조회 API
- 자동수집 스케줄 및 오류처리
- 예보 발표시각과 대상시각의 관리 방식

관련 기존 파일을 우선 검토한다.

- "kma-forecast.mjs"
- "kma-mid.mjs"
- "stats-engine.mjs"
- "stats-hourly.mjs"
- "stats-api.mjs"
- "server.mjs"
- 기타 DB, 프런트엔드, 마이그레이션 관련 파일

파일 구조나 DB 구조는 실제 최신 소스를 기준으로 확인한다.

기존 메뉴, 화면, API, 인증, 데이터 수집, 통계 계산 및 다운로드 기능을 삭제하거나 기존 동작을 변경하지 않는다.

신규 분석 기능은 가능하면 별도 모듈로 구현하고 기존 시스템에 연결한다.

3. 과거 평균 비교 기준 — 핵심 요구사항

모든 실시간 날씨 분석과 향후 예보 비교에서 다음 세 가지 과거 평균을 지원한다.

A. 1990년 이후 전체 평균

- 시작 연도: 1990년
- 종료 연도: 비교 기준 연도의 직전 완료 연도
- 예: 2026년에는 1990~2025년
- 가장 장기적인 기온·강수 특성을 파악하는 기준

B. 최근 10년 평균

- 현재 진행 중인 연도를 제외한 최근 완료 10개 연도
- 예: 2026년에는 2016~2025년
- 매년 자동으로 변경

C. 최근 5년 평균

- 현재 진행 중인 연도를 제외한 최근 완료 5개 연도
- 예: 2026년에는 2021~2025년
- 매년 자동으로 변경

고정 연도값을 소스에 하드코딩하지 않는다.

선택된 비교 날짜를 기준으로 과거 평균을 계산하되, 현재 서비스의 실시간 분석에서는 완료된 전년도까지를 사용한다.

과거 특정 연도를 대상으로 분석할 경우에는 해당 연도의 미래 데이터가 비교 기준에 섞이지 않도록 별도로 처리한다.

화면 표시 방법

사용자가 다음 중 선택할 수 있도록 한다.

- 전체 평균
- 최근 10년 평균
- 최근 5년 평균
- 전체 비교

기본값은 전체 비교로 한다.

전체 비교에서는 현재 관측값 또는 예보값과 세 가지 과거 평균을 동시에 표시한다.

예시:

구분| 기온| 현재 대비 차이
현재 기온| 27.5℃| -
1990년 이후 평균| 22.1℃| +5.4℃
최근 10년 평균| 23.4℃| +4.1℃
최근 5년 평균| 24.2℃| +3.3℃

세 비교 기준은 모든 신규 분석 화면에서 공통 컴포넌트와 동일한 설정 방식을 사용한다.

과거 평균 계산 기준

1. 시간별 기온 비교는 과거 같은 계절의 동일 시간대를 기준으로 한다.
2. 기본 시간대 비교는 같은 월일의 ±7일, 동일 시각을 활용한다.
3. 기간별 기온 평균은 대상 기간의 시간·일 범위와 일치시킨다.
4. 최근 5년, 10년, 전체 기간에 동일한 계산 공식을 적용한다.
5. 특정 연도에 관측값이 적을 때 표본 수가 적은 연도가 과도한 영향을 주지 않도록 연도별 가중 기준을 명확히 설계한다.
6. 일별 최고·최저기온은 같은 일별 지표끼리 비교한다.
7. 강수량은 대상 기간별 총강수량 또는 같은 시간 간격의 강수량끼리 비교한다.
8. 강수확률과 실제 강수량은 혼합하지 않는다.
9. 윤년, 2월 29일, 연말·연초의 비교 기간을 처리한다.
10. 결측값을 0으로 간주하지 않는다.

관측값이 충분하지 않은 지점·기간은 평균을 임의로 계산하지 않고 '비교 데이터 부족'으로 표시한다.

평균 계산 시 실제 사용한 연도 범위, 유효 연도 수, 표본 수를 조회할 수 있게 한다.

'1990년 이후 평균'은 이 서비스에서 자체 계산한 통계이며, 기상청 공식 기후평년값과 혼동되지 않도록 명칭과 설명을 구분한다.

4. 신규 메뉴 ① 오늘의 날씨

기존 날씨 통계와 별도로 "오늘의 날씨" 메뉴를 추가한다.

실시간 관측과 과거 통계를 결합하는 메인 화면이다.

주요 기능

4-1. 현재 기상정보

- 현재 기온
- 상대습도
- 1시간 강수량
- 강수형태
- 풍속 및 풍향
- 관측지점
- 마지막 관측시각 및 데이터 출처

데이터 갱신이 지연되었다면 현재값으로 오인되지 않게 한다.

4-2. 과거 평균 비교

현재 기온과 다음 평균을 비교한다.

- 1990년 이후 평균
- 최근 10년 평균
- 최근 5년 평균

현재 대비 온도 차이를 함께 표시한다.

강수량, 습도, 풍속도 데이터가 충분하면 동일한 방식으로 확장한다.

4-3. 과거 기온 분포 및 순위

현재 시각의 기온이 과거 같은 계절·시간대의 분포에서 어느 위치에 있는지 분석한다.

- 백분위
- 상위 또는 하위 순위
- 과거 최고·최저값
- 평년 범위를 벗어난 정도

세 기준기간 각각의 백분위를 제공한다.

표본 부족 시 순위를 표시하지 않는다.

4-4. 오늘의 시간별 기온 그래프

그래프에는 다음 항목을 제공한다.

- 오늘 실제 관측기온
- 향후 시간별 예보기온
- 1990년 이후 평균
- 최근 10년 평균
- 최근 5년 평균

과거 평균 세 개는 각각 표시·숨김이 가능해야 한다.

현재 관측과 미래 예보는 선 종류, 음영 또는 구분선으로 명확하게 구분한다.

예보값을 실제 관측값처럼 연결하거나 표현하지 않는다.

4-5. 오늘의 날씨 이야기

통계 결과를 기반으로 자동 설명문을 생성한다.

예시:

"오늘 서울은 1990년 이후 같은 시기보다 상당히 더운 날입니다. 다만 최근 5년 평균과 비교하면 기온 차이가 상대적으로 작습니다."

수치는 반드시 DB에서 계산한 결과를 사용한다.

통계의 차이가 미미하면 특별한 현상이라고 과장하지 않는다.

5. 신규 메뉴 ② 날씨 예보

"날씨 예보" 메뉴를 추가한다.

일반적인 예보 제공을 넘어 미래 날씨가 과거와 얼마나 다를지 비교하는 기능을 구현한다.

5-1. 시간별 예보

- 시간별 기온
- 강수확률 및 예상 강수량
- 강수형태
- 습도
- 풍속
- 하늘상태
- 예보 발표시각

시간별 예보기온을 과거 3개 기준기간의 같은 시기·시간대 평균과 비교한다.

5-2. 주간 예보

- 날짜별 최고·최저기온
- 강수확률
- 제공되는 기간의 강수량 전망
- 날씨상태
- 일별 과거 3개 기준기간 평균
- 기준기간 대비 예상 기온 차이

단기예보와 중기예보를 기간별로 연결한다.

두 예보가 겹치는 날짜는 신뢰할 수 있는 최

[…원문 약 2,300자 전달 누락 — 6·7절 및 8절 앞부분…]

카드가 반복되지 않도록 한다.

표현 방식

- 간결한 제목
- 핵심 수치
- 3가지 과거 비교 평균
- 설명문
- 근거 데이터
- 비교 기간
- 자료 기준시각

초기에는 계산 결과를 문장 템플릿에 적용하는 규칙 기반 방식으로 구현한다.

LLM을 사용하더라도 수치·순위·통계적 판단을 임의로 생성하게 해서는 안 된다.

실황 또는 예보가 없으면 만들어낸 데이터로 대체하지 않는다.

9. 통계 엔진 공통화

각 메뉴에서 같은 통계를 중복 계산하지 않는다.

기존 통계 엔진을 최대한 재사용하고, 부족한 부분만 신규 모듈로 확장한다.

예상 기능:

- 과거 기준기간 생성
- 지점별 과거 평균 산출
- 시간별 과거 분포 계산
- 현재 관측값과 과거 비교
- 예보값과 과거 비교
- 백분위 및 순위 계산
- 지역별 비교
- 유사일 탐색
- 날씨 이야기 후보 생성

모든 기능에서 동일한 비교 기준을 사용한다.

API 응답에는 가능한 경우 다음 정보를 포함한다.

- 관측지점
- 대상시각
- 자료 종류와 출처
- 현재 관측값 또는 예보값
- 예보 발표시각
- 1990년 이후 평균
- 최근 10년 평균
- 최근 5년 평균
- 각 평균 대비 차이
- 표본 수 및 자료 보유기간
- 결측·품질 상태

기존 API와 호환되지 않는 변경은 금지한다. 신규 엔드포인트를 사용하는 방향을 우선한다.

통계 조회 성능을 위해 공통 집계와 캐싱을 검토한다. 캐시 키에는 관측지점, 통계지표, 비교기간, 기준연도, 자료 갱신 상태가 반영되어야 한다.

10. 관측과 예보 데이터의 정합성

이 기능은 정확성이 특히 중요하다.

다음 조건을 반드시 지킨다.

1. ASOS 관측지점과 동네예보 격자 위치를 동일한 지점이라고 가정하지 않는다.
2. 관측지점·격자·중기예보 구역 간 매핑 기준을 명확히 관리한다.
3. 관측과 예보를 데이터 모델에서 구분한다.
4. 예보 발표시각과 예보 대상시각을 별도로 관리한다.
5. 모든 날짜 및 시간 계산은 한국시간(KST)을 기준으로 처리한다.
6. 결측자료와 무강수 0을 구분한다.
7. 강수확률을 실제 강수량처럼 합산하지 않는다.
8. 예보값으로 기록 경신을 확정하지 않는다.
9. 데이터가 부족하면 불확실성을 표시한다.
10. 비교 기준기간마다 실제 포함된 연도 수와 자료 완전도를 관리한다.
11. 예보와 관측이 중복되는 시간에는 정해진 우선순위를 적용한다.
12. 데이터 공급 지연 시 이전 자료를 최신 자료처럼 표시하지 않는다.

관측지점별 ASOS 자료가 없는 기간은 해당 기간의 평균에 포함하지 않으며, 일부 연도가 누락되면 비교 결과의 신뢰도를 표시한다.

11. UI/UX 디자인 요구사항

기존 누니날씨의 디자인 시스템을 유지한다.

전체 웹사이트를 새로 디자인하지 않는다.

신규 기능은 기존 메뉴와 자연스럽게 통합한다.

공통 요구사항

- PC와 모바일 반응형 지원
- 지점 선택 UI 재사용
- 기간 선택 UI 재사용
- 기존 차트 스타일 재사용
- 과거 평균 3종 선택 기능 공통화
- 관측·예보를 시각적으로 구분
- 복잡한 조건은 간결하게 정리
- 화면 상단 조회조건이 과도하게 높아지지 않도록 구성

평균 비교 그래프

네 종류의 선을 지원한다.

- 현재 관측 또는 미래 예보
- 1990년 이후 평균
- 최근 10년 평균
- 최근 5년 평균

각 선을 개별 표시하거나 숨길 수 있어야 한다.

모바일에서는 범례와 카드가 자연스럽게 배치되어야 한다.

상세 평균 비교 결과에서는 선택한 시점의 수치와 기준별 차이를 함께 보여준다.

화면 배치 우선순위

1. 사용자가 바로 이해할 수 있는 핵심 결과
2. 과거 3개 기준 평균과의 비교
3. 기온 및 강수 변화 그래프
4. 통계 설명
5. 상세 조건과 원자료

12. 데이터 수집·관리 메뉴 확장

기존 관리 메뉴에서 실황과 예보 데이터를 관리할 수 있도록 한다.

자료수집

- 현재 수집 중인 데이터 종류 표시
- 데이터별 마지막 성공 수집시각
- 발표 회차별 수집 상태
- 수동 재수집
- 수집 오류 확인

미적재 현황

- 실황·예보별 누락 현황
- 관측지점별 누락 현황
- 수집 지연과 정상 미발표 상태 구분

수집이력

- 자료 종류
- 발표시각
- 수집시각
- 성공·실패 여부
- 수신 건수
- 오류 메시지

이미 운영 중인 수집 로직을 재사용하며 불필요한 외부 API 호출을 늘리지 않는다.

인증키 및 서비스 비밀정보가 브라우저나 로그에 노출되지 않도록 한다.

- 결측과 0을 정확히 구분하는지
- 평균 및 백분위가 독립적인 검산 결과와 일치하는지

- 단기·중기예보 연결
- 발표 회차별 저장정보 참조
- 관측과 예보의 중복 구간 처리
- 예보 부재·수집 지연 처리
- 지역별 예보 매핑 검증

- 기존 통계 메뉴 정상 작동

DB 구조 변경이 필요하면 기존 데이터를 보존하는 마이그레이션을 작성한다.

운영 DB를 직접 초기화하거나 기존 테이블을 삭제하지 않는다.

변경 후 기존 기능을 회귀 테스트하고, 테스트 실패 상태를 완료로 보고하지 않는다.

최종 목표

현재 누니날씨는 과거 기상자료를 이용해 날씨의 변화를 분석하는 서비스이다.

이번 개발을 통해 다음 질문에 답할 수 있는 서비스로 확장한다.

- 지금 날씨는 예전보다 얼마나 다른가?
- 최근 5년과 비교해도 특별한 날씨인가?
- 최근 10년과 1990년 이후 평균은 얼마나 다른가?
- 앞으로의 날씨는 과거 같은 시기와 얼마나 다를까?
- 오늘 가장 이야기할 만한 날씨 현상은 무엇인가?

기존 통계 기능을 보존하면서 1990년 이후 전체, 최근 10년, 최근 5년의 세 가지 비교 기준을 전체 서비스에 일관되게 적용하는 것을 핵심 개발 목표로 한다.

기존 시스템 분석 결과를 바탕으로 단계별로 구현하되, 이미 구현된 기능은 재사용하고 불필요한 재개발은 하지 않는다.
