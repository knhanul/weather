## 1단계 · 기존 시스템 분석 및 데이터 검증 (2026-10-13 19:40 KST)
- 운영 DB(NAS MySQL weatherhub) 확인 결과:
  - ASOS 시간자료·일자료: 8개 지점 모두 1990-01-01 ~ 2026-10-12. 시간자료는 매일 11:30 에 전날까지 들어온다(오늘 관측은 ASOS 에 없음).
  - 초단기실황(kma_ultra_ncst): 2026-10-12 00시부터, 매시, 8항목(T1H·RN1·REH·PTY·WSD·VEC·UUU·VVV). 격자 기준(관측소가 아님).
  - 초단기예보(kma_ultra_fcst)·단기예보(kma_vilage_fcst): 2026-10-10 발표분부터, 발표시각(base)·대상시각(fcst)·항목별로 따로 보관. 단기예보는 발표 하나에 약 4~5일 앞까지(TMP·POP·PCP·SKY·PTY·REH·WSD·TMX·TMN 등).
  - 중기예보(kma_mid_items): 06·18시 발표, 4~10일 뒤(육상 wf·rnSt, 기온 taMax·taMin 과 범위), 중기전망 글(wfSv).
  - 지점→격자(weather_stations.nx,ny)와 지점→중기 구역(kma_mid_regions) 표가 따로 있다. 서울 108 = 격자 60,127, 중기 기온 11B10101.

- 회귀 기준: 기존 공개 API 응답 해시(scripts/rt-regress.sh)를 운영과 비교.
- 확인 중 발견: 초단기예보는 발표 기록(kma_fcst_releases)에 HH:30 으로, 실제 행(base_datetime)에는 기상청 item 의 HH:00 으로 저장된다. 읽을 때 '발표 기록 이하의 가장 최근 행 묶음'을 쓰도록 처리(저장 방식은 그대로).

## 2단계 · 과거 3개 기준 평균 엔진 (2026-10-13 19:50 KST, 배포 7b34d03)
- 새 모듈 rt-baseline.mjs(기존 stats-engine 계산은 손대지 않음, 같은 메모리 저장소를 읽기만 함).
- 기준기간은 비교 날짜의 연도에서 계산: 1990년 이후(자료 첫해~전년), 최근 10년, 최근 5년. 2026년 → 1990~2025 / 2016~2025 / 2021~2025, 2027년 → 1990~2026 / 2017~2026 / 2022~2026. 과거 연도를 분석하면 그 해 이전만 씀.
- 같은 시기 = 같은 월일 ±7일(15일), 같은 정시. 2/29 는 평년에 2/28. 연초 창은 앞 해 12월을 포함하고, 기준 끝(전년 12/31) 뒤 날짜는 잘라 냄.
- 해마다 평균을 먼저 내고 해끼리 같은 무게로 평균. 해 안 유효값이 절반 미만이면 그 해 제외, 유효한 해가 80% 미만이면 '비교 데이터 부족'. 백분위·순위는 표본 60개 이상일 때만. 결측(행 없음·품질 9)은 빼고 0 은 값.
- 새 API: GET /api/rt/baseline?station=&date=&hour=&field=ta|hm|rn|ws(또는 daily=max|min|avg|rain)&value= → 기준별 평균·차이·유효 연도 수·표본 수·빠진 해·백분위·순위·10~90% 범위·과거 최고·최저(날짜).
- 검증: 단위 테스트 12건 통과(기준기간·새해 이동·2/29·연말연초·누락 연도·결측/0·독립 검산 백분위). 운영 NAS 에서 SQL 로 따로 계산한 값과 18개 경우(서울 19시, 제주 2/29, 부산 1/2 연초, 대구 8/1, 일최고 2건 × 3기준) 평균·유효 연도·표본·백분위 모두 일치.

## 3단계 · 오늘의 날씨 메뉴 (2026-10-13 20:00 KST, 배포 7b34d03)
- 왼쪽 메뉴 맨 위 '오늘의 날씨'(#/today?station=&basis=). 기존 메뉴·화면·API 는 그대로.
- 화면: 현재 실황(기온·습도·1시간 강수·강수형태·바람, 관측 시각·출처, 90분 넘게 늦으면 '지연' 표시와 취소선) → 3개 기준 비교 → 날씨 이야기 → 시간별 그래프(실황 실선, 예보 점선 + 음영 + '지금' 선, 평균 3선 켜고 끄기, 누르면 그 시각 값과 기준별 차이) → 같은 시기 분포(백분위·순위·보통 범위·과거 최고/최저) → 오늘 최고·최저 예보 vs 공식 일자료 평균 → 습도·강수·바람 비교 → 계산 기준(접힘).
- 기준 선택(전체 비교 기본 / 1990년 이후 / 최근 10년 / 최근 5년)은 공통 NWBasis(주소 basis + 저장)로 만들어 다음 메뉴에서도 같은 방식으로 씀.
- 새 API: GET /api/rt/today?station= (지점별 60초 캐시). 같은 시각 우선순위: 실황 > 초단기예보 > 단기예보. 예보는 발표시각을 같이 줌. 실황은 격자 값이라 'ASOS 관측소 위치와 같지 않을 수 있음'을 밝힘. 최고·최저 예보는 '기록은 관측으로만 확정'.
- 이야기: 규칙 기반 문장(차이 1℃ 미만은 '비슷', 과장 없음), 실황이 늦으면 '지금' 문장을 만들지 않음. 수치는 모두 위 계산값.
- 검증: e2e rt-today.mjs(모바일 390×844·데스크톱) 시험 컨테이너·운영 모두 ALL PASS — 모바일 본문 시작 19%, 가로 넘침·콘솔 오류 없음. 기존 공개 API 154개 응답이 운영과 동일(프로세스 카운터 dataVersion·health db_ms 제외). 기존 e2e nav(로그인 부분 제외)·fold·drawer 통과. 단위 테스트 전체 323 중 실패 7개는 이전 커밋(03f5b4b)에서도 같은 7개(브랜드·공유카드·auth 스키마, 무관).

- 왼쪽 메뉴 '날씨 예보'(#/forecast?station=&basis=). 새 API GET /api/rt/forecast?station= (60초 캐시), 새 모듈 rt-forecast.mjs(순수 함수).
- 이번 주(월~일) 예년 대비: 지난 날 = 공식 일자료 관측, 오늘부터 = 예보. 최고·최저기온 각각 (값 − 같은 시기 ±7일 공식 일자료 평균)의 평균을 3개 기준으로. '관측 n일 + 예보 m일' 표시.
- 주간 예보(오늘~10일 뒤): 우선순위 — 그 날 TMX·TMN 이 있는 가장 최근 단기예보 > 가장 최근 중기기온. 날씨·강수확률은 단기(하루 6시간 이상 있을 때) > 중기육상(오전·오후). 강수확률은 하루 최댓값(더하지 않음), 예상 강수량은 숫자인 시간만 더하고 '1mm 미만'은 시간 수로 따로. 날짜마다 출처와 발표시각. 같은 시기 과거 최고 1℃ 안이면 '근접(예상)' — 기록 확정 아님.
- 시간별(약 3일): 6시간 안은 초단기예보, 그 뒤 단기예보. 기온마다 같은 날짜 ±7일 같은 정시 3개 평균과 차이, 그래프(예보 점선 + 평균 3선 켜고 끄기), 표는 접어 둠.
- 발표별 예보 변화: 날짜마다 단기 TMX·TMN 과 중기 taMax·taMin 의 발표 회차별 값(값이 바뀐 회차만 표시).
- 매핑: 단기 = 격자, 중기기온 = 도시 구역, 중기육상 = 광역 구역 — 화면 '계산 기준'에 지점별로 밝힘.
- 검증: 단위 테스트 rt-forecast 3건(우선순위·강수확률 미합산·중기 날짜·변화 이력), e2e rt-forecast(모바일·데스크톱) 시험·운영 ALL PASS(모바일 본문 시작 17%), rt-today·nav ALL PASS, 기존 API 154개 운영과 동일. 운영 백업 app.prev-7b34d03(+31e6cb5).
