# 날씨 통계 — 현재 구현·자료 조사 (2026-10-11)

'날씨 통계' 확장(사용자 요구 t120u) 전에 실제 소스와 NAS MySQL(`weatherhub`)을 직접 확인한 결과.
수치는 2026-10-11 06:30~07:00 KST 에 운영 DB 에서 직접 센 값이다(조사 스크립트는 저장소에 넣지 않음, 쿼리는 아래에 요약).

## 1. 앱 구조 (재사용 범위)

| 구분 | 실제 구현 |
|---|---|
| 서버 | `server.mjs` — 의존성 없는 `node:http` 서버, 경로를 `if (req.method === "GET" && url.pathname === …)` 로 나눔. 정적 파일 `public/` |
| 화면 | `public/index.html` 한 파일(바닐라 JS, 해시 라우팅 `#/…`, `route()`·`show()`·`PAGE_HEAD`). 프레임워크·차트 라이브러리 없음 — **차트는 직접 그린 SVG**(`drawChart`, 툴팁 `.tip`) |
| 저장소 | `db.mjs`(PostgreSQL, 되돌리기용) → `DB_DRIVER=mysql` 이면 각 함수 첫 줄에서 `db-mysql.mjs` 로 넘김. JSON 파일 모드(로컬 개발)도 남아 있음 |
| 권한 | `auth.mjs` `guard()`: 로그인 기능이 켜져 있으면 GET 이 아닌 요청과 `/api/gaps`·`/api/jobs`·`/api/admin/*` 만 관리자. 그 밖의 GET(`/api/series`, `/api/daily`, `/api/export` …)은 공개 조회 |
| 대시보드 | `#/` — 지점 버튼(`stSel`, 지연 표시), 기간 바로가기(24시간~30일 = 시간자료, 3~24개월 = 공식 일자료), 직접 지정, 통계 줄(`chartStats`), SVG 차트(기온 선 + 오른쪽 축 강수 막대, 일 단위면 최고~최저 띠), 아래 시스템 카드(`dashCards`). 자료: `/api/dashboard`(지점·요약), `/api/series` |
| 요약표 | `hourly_month_stats`(지점×월×dataset), `hourly_day_stats`(지점×일 시각 수), `daily_station_stats`(지점별 일자료 행 수), `hub_stats_meta`. 저장(`upsertHourly`/`upsertDaily`) 때 건드린 지점·월만 다시 셈 |
| 기존 다운로드 | `/api/export`(원자료 CSV, 컬럼 선택, `kind=hourly|daily`), `/api/export/preview`, `/api/export/fields`, 레이아웃 저장 |

재사용: 대시보드 차트·지점 버튼·기간 바로가기는 그대로 '한눈에 보기' 탭의 주 그래프로 둔다. 새 통계 그래프는 같은 SVG 방식(같은 색·글꼴·툴팁 스타일)으로 새로 그린다(기존 `drawChart` 는 시간축 전용이라 연도·월일 축에 맞지 않음).

## 2. 저장·조회 방식

- **시간자료** `observations_hourly` — 기본키 `(station_id, observation_datetime, provider, dataset)`, `observation_datetime` 은 KST 벽시계 문자열(16자 `YYYY-MM-DD HH:MM` 과 19자 `…:SS` 가 섞여 있어 조회 때 16자로 접음, 서울·광주 2025~2026 일부 중복). 기본 6개 + 기상청 응답 34개 항목 전부 + `raw`.
- **공식 일자료** `observations_daily` — 기본키 `(station_id, observation_date)`, 기상청 일자료 59개 항목 + `raw`. 저장된 행은 전부 `source_kind='OFFICIAL'`(107,450행). 시간자료 집계 행(DERIVED)은 저장하지 않고 `/api/daily` 가 그때그때 만든다.
- **시간자료 기반 일집계** — `server.mjs deriveDaily()`: 공식 일자료가 없는 날만 정시값 평균·최고·최저·합. `source_kind: "DERIVED"`, 화면에 '시간자료에서 집계'. 공식 일최고·일최저와 다르다(정시 관측의 최댓값일 뿐).
- 시각 기준: 모두 Asia/Seoul(KST) 벽시계. 날짜 경계 = KST 자정.

## 4. 강수 '공란'과 결측의 구분

- 공식 일자료에서 `sumRn` 이 빈 문자열(→ NULL)인 날은 전체의 52~68%. 강수일수(0.1mm 이상)의 상식적 크기(서울 연 100일 안팎)와 맞고, 그런 날의 일기현상은 박무·연무 등 비가 없는 현상뿐이었다(예: 서울 2024-07-01 `sumRn:""`, `iscs:"{박무}0010-…"`).
- NULL 인데 일기현상에 `{비}`/`{소나기}` 가 적힌 날은 지점당 36년간 0~5일, 모두 20~40분짜리 짧은 비(측정 불가 미량으로 보임).
- `0.0` 은 눈·진눈깨비 등 흔적 강수가 있었던 날(예: 서울 1990-01-01 `{눈}`).
- 일자료 API 에는 강수 품질 플래그가 없다. 그래서 **"그날의 공식 일자료 행이 있으면 공란 = 무강수(0으로 집계), 행이 없으면 자료 없음"** 으로 정한다. 행은 있는데 기온·강수가 모두 비어 있는 날(현재 0건)은 강수도 자료 없음으로 본다. 화면 계산 기준에 이 규칙을 그대로 적는다.
- 시간자료는 `rn_qcflg = '9'` 이면 결측, 공란이면서 플래그가 없으면 무강수로 볼 수 있다(2단계 시간자료 통계에서 적용).
