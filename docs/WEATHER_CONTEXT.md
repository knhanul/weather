# 오늘·최근 비교 / 선택형 날씨 배틀 / 절기·복날 이야기

WEB weather + 스마트폰 inal 공통 비교 엔진은 `weather-context-engine.mjs`, 오늘의 동일격자 초단기실황 어댑터는 `grid-context.mjs`입니다.
API 세 개는 읽기 전용 GET이며 기존 수집·로그인·저장 스키마를 바꾸지 않습니다.

- `/api/stats/context-today?station=108`
- `/api/stats/context-battle?station=108&date1=2026-11-06&opponent=yesterday&period=exact&criteria=cooler,dry,calm`
  - opponent: yesterday / week / year / custom(date2 필요)
  - period: exact / recent5 / recent10 / all
  - criteria: warmer / cooler / dry / calm (복수 선택). 온도 0.5℃, 강수 0.1mm, 풍속 0.5m/s **이하** 차이는 무승부. 서비스 기준이지 기상청 공식 기준이 아닙니다.
- `/api/stats/context-season?station=108&name=입춘&year=2025`

## 화면

- 오늘 날씨: 현재 날씨 카드 다음에 최근 비교. 모바일은 같은 첫 슬라이드 안에 간단한 요약 + 펼치는 그래프/표.
- 날씨 이야기 → 날씨 배틀: 원하는 승리 조건·상대 날짜·과거 기간을 고르는 새 비교. 첫 조회는 가장 최근 완료 관측일로 시작하고, 기준 날짜를 오늘로 바꿀 수도 있습니다. 기존 해마다 상세 비교는 보존.
- 날씨 이야기 → 절기·복날 이야기: 지역·연도·절기 선택. 초·중·말복과 24절기 모두 지원.
- `public/weather-context.mjs`는 두 저장소에 동일 복사본으로 둡니다. 변경 시 양쪽 동기화하고 양쪽 테스트를 돌립니다. CSS는 `.wc` 안에 한정됩니다.

## 자료 제한과 비교 원칙 (중요)

1. 오늘·어제·최근7일은 **동일 5km 격자의 초단기실황**끼리만 계산합니다. 기존 `rt.gridOf` → `rt.ncst` → `kma_ultra_ncst`를 사용합니다. ASOS 관측소 원본이나 예보와 섞지 않고, 화면에 격자 좌표·출처·KST 기준 관측시각을 명시합니다.
2. ASOS 배치 원본이 D-1/D-2까지인 것과 NAS의 오늘 실황 부재는 다른 문제입니다. 오늘 비교는 이미 적재된 NCST의 오늘·어제·직전7일 같은 정시를 사용합니다. 해당 격자의 오늘 기온이 없을 때만 비교 시각 미정이며 ASOS/예보로 대체하지 않습니다. 그 경우 `recent7.days=null, computed=false`는 미계산이지 과거 자료0개가 아닙니다. 새 수집·마이그레이션 없음.
3. 최근 7일은 오늘 제외·같은 정시 평균, 실제 일수/7 표시. 시간별 기온은 관측만, 결측선은 끊습니다. 최근 7일 최고·최저는 완료된 공식 일자료만 표시.
4. 강수·바람·습도 차이는 각각 1mm·2m/s·10%p 이상일 때만 덧붙입니다. 강수는 그 정시 직전 **1시간**. 하루 누적과 혼합하지 않습니다.
5. 배틀에서 오늘이 포함되면 양쪽 모두 같은 정시 관측(강수도 같은 직전 1시간)만 비교합니다. 완료된 과거 날짜끼리는 일평균기온·일강수량·일평균풍속. 예보는 사용하지 않습니다.
6. 최근 5/10년·전체는 상대 **월·일**의 완료된 과거 연도 평균과 기준 날짜를 비교합니다. 그 자체가 5개/10개 관측을 보장하지 않습니다. 실제 보유 범위·유효 해 수·소표본 안내를 표시. 2/29가 없는 해는 제외하고 2/28이나 3/1로 바꾸지 않습니다.
7. NCST의 빈값·결측코드(절댓값900이상)·비물리 풍속/습도는 0으로 바꾸지 않습니다. RN1 수치0.5는0.5mm 그대로이며 무강수로 치환하지 않습니다. "강수없음"만0mm로 해석하고, 범위/미량/trace는 정확한 수치차이를 내지 않습니다. ASOS 배틀/이야기에서 없는 관측은 0이 아니고 비교 불가입니다. 강수 공란은 기존 ASOS 정규화 정책(행과 기온이 있는 공식 일자료의 공란은 무강수, 시간자료 QC 9는 결측)을 그대로 사용합니다. JSON 로컬 시드 자료는 API에서 비교를 거부합니다.
8. 절기 날짜: Astronomy Engine 2.1.19가 태양의 겉보기 황경을 계산한 시각을 KST 날짜로 변환. 고정 2/4·11/7 등의 근삿값이 아닙니다. 복날은 lunar-javascript 1.7.7 **일간**만 사용해 하지 3·4번째 경일 / 입추 첫 경일(당일 포함)을 계산합니다. 중국 음력 날짜는 사용하지 않습니다. 지원 1970~2050년. 출처 링크는 API·화면에 있습니다.
9. 해당일과 주변 14일(앞뒤 7일, 해당일 제외) 비교, 선택한 해와 여러 해 결과를 분리. 여러 해 평균 차이는 해당일과 주변 14일이 모두 있는 **짝지은 해**만 사용. 관측/기대 일수와 제외 해 수 표시. 절기가 기온 변화를 일으킨다는 인과 주장은 하지 않습니다.
10. 입동 첫 영하는 9~다음해 2월, 입춘 후 영하는 다음 30일, 동지 겨울은 12~다음해 2월. 결측·진행 중이면 잠정임을 명시. 윤년 2/29 포함.

## 검증 / 배포 전

- `node --test scripts/weather-context.test.mjs scripts/grid-context.test.mjs` (순수 엔진·API·달력 회귀)
- 전체 `npm test`, `npm run typecheck`도 실행. 기존 main에 있는 테스트/빌드 실패는 별도 보고하며 이번 기능 성공으로 숨기지 않습니다.
- 운영은 현재 `server.mjs` + `public/` 경로를 확인해야 합니다. 저장소에는 별도 TanStack/Vercel 앱도 공존하며 루트 Dockerfile은 그 앱 빌드 대상입니다. 이를 이번 작업에서 임의 전환하지 않습니다.
- **weather 먼저** 적용 후 inal의 읽기 전용 프록시·정적 파일 적용. Node 실행 환경에도 새 운영 의존성 2개가 필요하므로 `npm ci --omit=dev` 필요.
- DB 마이그레이션 없음. 데이터·.env·settings·다른 서비스 변경 없음. 운영 배포와 main push는 미리보기 승인 전에는 하지 않습니다.
- 루트 `npm run build`는 `db:migrate`를 이어 실행하므로 시험 시 반드시 DATABASE_URL 없는 격리 환경에서만 실행합니다.

## 2026-11-08 audit / 운영 배포 메모

- 실제 운영은 OVH `/srv/weather-hub`, `/srv/inal`의 커스텀 Docker Compose입니다. weather 컨테이너는 `node server.mjs`, inal은 `node server/proxy.mjs`; 루트 TanStack/Vercel Dockerfile을 적용하지 않습니다.
- OVH weather 커스텀 Dockerfile의 최소 의존성 목록(pg/mysql2)에 astronomy-engine@2.1.19 및 lunar-javascript@1.7.7을 추가해야 합니다. 루트 앱 전체를 빌드하지 않습니다.
- 공유 화면의 성공 응답 캐시는 최대 64개·직렬화 크기 추산 1MiB이며 현재30초/배틀60초, 절기 600초, 관측소 30분입니다. 요청 타임아웃 15초, 새 조회/화면 해제 시 취소. 오류는 캐시하지 않습니다. inal 프록시에도 기존 TTL이 있습니다.
- 절기 여러 해 조회는 지점 일자료 저장소를 한 번 얻은 뒤 메모리 배열에서 계산하며 연도마다 DB를 질의하지 않습니다.
- 시간자료 배틀의 지원 기간은 일자료가 아니라 실제 시간자료 범위로 결정합니다. 지원 범위 밖 날짜는 표본 후보에서 제외합니다. 입춘 이후 최저 관측이 하나도 없으면 영하 일수는 null(0일 아님).
- 최초 영하 탐색은 선택 연도 9월~다음 해 2월(윤년 포함) 관측 중 첫 영하입니다. 결측이 있으면 진짜 최초일을 확정하지 않습니다.
- 로컬 미리보기 스냅샷/프록시 서버는 `/workspace/weather-context-preview/`에만 있으며 운영 배포 패키지에 넣지 않습니다. 운영 계산은 기존 statsData/statsHourly의 실제 NAS ASOS 자료만 사용합니다.

## 2026-11-08 동일격자 실황 수정

- backend는 한 격자의 과거7일 00시~오늘 현재정시까지 인덱스 범위조회 한 번만 하며 동일 요청을 합칩니다. 성공 원본 캐시는30초·최대16개 격자/시각키. 긴 ASOS 시간자료를 오늘 API에서 읽지 않습니다.
- frontend는 `basis=grid-v1`로 구 ASOS 응답과 캐시키를 분리하고, inal 프록시가 이를 보존합니다. 현재 화면/프록시 TTL30초. 배포 시 inal 프로세스 재생성으로 구 메모리 캐시를 비웁니다.
- 최근 일최고/최저 표는 **별도 ASOS 완료 일자료**이며 오늘 진행중인 극값이나 격자 정시 최댓값을 하루 극값처럼 사용하지 않습니다.
- 출처: https://www.data.go.kr/data/15084084/openapi.do (초단기실황은 대표 AWS 관측, RN1/T1H/WSD 실수값); https://apihub.kma.go.kr/apiList.do?seqApi=10 (실황과 예보 분리, RN1=1시간강수량). RN1의 문자열 범위를 다른 서비스처럼 임의 중간값으로 치환하지 않습니다.
